# Kuma Plugin Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a lean Claude Code plugin named `Kuma` that delegates review and task execution to `opencode-go`, `opencode-zen`, and `ollama-cloud` through `opencode` and `pi`, while keeping Claude Code as the orchestrator.

**Architecture:** Reuse Codex plugin behavior where it already works, but narrow the public surface to `setup`, `models`, `review`, `task`, `status`, `result`, and `cancel`. Use a single local bridge script (`kuma-companion.mjs`), two thin backend adapters, and a compact local model index sourced from BaseLLM with pydantic fallback.

**Tech Stack:** Node.js 18.18+ with `.mjs` modules, `bun` for dependency install and test execution, Zod for normalization/validation, built-in `fetch` for HTTP, line-delimited JSON over stdio for `pi` RPC.

**Spec:** `/d/Everything/Furaidē/claude-code/docs/superpowers/specs/2026-06-23-kuma-v1-spec.md`

**Reference impl:** `/tmp/opencode/codex-plugin-cc/plugins/codex/`
