# Web Tools v0.1 Design

**Date:** 2026-06-18
**Status:** Draft, current agreed baseline
**Scope:** opencode web-tools plugin v0.1 (`web_search`, `fetch_content`, `maps_search`)

---

## Goal

Add a native opencode plugin that exposes three model-callable web tools with lean responses, cost-aware provider defaults, interactive user configuration, and provider-usage tracking.

The plugin replaces ad-hoc CLI orchestration for the most common web lookup flows while keeping the response surface intentionally small and predictable for the calling model.

This spec captures the **currently agreed v0.1 baseline**. It is intentionally separate from the session-vault cleanup spec because the web-tools design is still subject to further refinement before execution planning.

---

## v0.1 Scope

### In scope

Three tools:
- `web_search`
- `fetch_content`
- `maps_search`

Three providers:
- `gemini`
- `brave`
- `tavily`

Shared features:
- plugin-based tool registration using opencode's custom-tools/plugin API
- config-driven defaults via `web-tools.yml`
- `/tools-config` command for interactive config updates
- lean tool responses (only the minimum fields needed by the model)
- per-tool recording tables for `web_search` and `fetch_content`
- provider usage / budget tracking for `gemini`, `brave`, and `tavily`
- in-memory cache plus async DB sync for `web_search` and `fetch_content`

### Out of scope

- `video_search` (explicitly deferred to the next update)
- `code_search` (owned by `@karasutengu--docs-scout` via `ctx7` / `gh` directly)
- `exa` integration in the plugin (users rely on native opencode `websearch` for Exa free tier)
- semantic retrieval cache (v0.2 will build it from recorded data)
- built-in readability extraction for HTML-to-markdown without provider help

## Architecture

`web-tools` is a local opencode plugin loaded through `opencode.jsonc`.

It registers three tools through `@opencode-ai/plugin`'s `tool()` helper:
- `web_search`
- `fetch_content`
- `maps_search`

The plugin loads one shared config file, one shared provider-usage table, one shared pricing helper, and per-tool cache/recording helpers at initialization. Tool execution returns the smallest useful response to the model while persisting richer metadata asynchronously in local storage for future cache and budget decisions.

## Provider set and default posture

### Providers in v0.1

| Provider | Used for | Why it stays |
|---|---|---|
| `gemini` | `web_search`, `fetch_content`, `maps_search` | grounding quality, URL context, maps grounding, cost can be approximated from token metadata |
| `brave` | `web_search` | predictable cost, cheapest paid search, good filters (`freshness`, domains, country) |
| `tavily` | `web_search`, `fetch_content` | good extraction / crawl / map behavior, useful structured search surface |

### Providers intentionally excluded from v0.1

| Provider | Why excluded |
|---|---|
| `exa` | use native opencode `websearch` / `webfetch` free tier instead of duplicating paid integration in the plugin |
| `serper` | explicitly removed from scope |
| `ctx7`, `gh` | moved out of the plugin; `@karasutengu--docs-scout` owns code/doc lookup |

### Cost-aware default order (approved)

**Proposal 4: brave-first**

```yaml
webSearch:
  defaultProvider: brave
  primaryFallbackOrder: [brave, tavily, gemini]
  reserveFallbackOrder: []

fetchContent:
  defaultProvider: gemini
  primaryFallbackOrder: [gemini, tavily]
  reserveFallbackOrder: []

mapsSearch:
  defaultProvider: gemini
```

Rationale:
- `brave` is the cheapest predictable paid search path and supports the filters `gemini` lacks.
- `gemini` URL context is near-free compared with other extraction providers because it is token-billed rather than separately grounded.
- `maps_search` is gemini-only in v0.1.

## Tool 1: `web_search`

### Purpose

Search the web and return the minimum useful fields to the model. More detailed provider data is recorded in the background, not returned inline.

### Exposed tool args

Only the fields common across the approved provider set are exposed directly to the model:

```ts
{
  query: string              // required
  count?: number             // default from config
  freshness?: "pd" | "pw" | "pm" | "py"   // default from config
  raw_content?: boolean      // default from config
}
```

Everything else is config-only.

### Config-owned options

Examples (not exhaustive):
- `defaultProvider`
- `primaryFallbackOrder`
- `reserveFallbackOrder`
- `depth`
- `answer`
- `min_score`
- `include_domains`
- `exclude_domains`
- `country`
- `topic`
- `include_images`
- `highlights`
- provider-specific settings like `brave.goggles`

### Response

```ts
{
  results: Array<{
    title: string
    url: string
    snippet: string
    published?: string
    score?: number
    content?: string
  }>
}
```

Nothing else is returned to the agent. Provider name, grounding metadata, latency, ignored args, answer text, image data, and fallback history are recorded in the DB only.

### Recording table

`web_search_results`

Dedup key: `(url_hash, provider)`

Stored fields include:
- normalized url
- title
- snippet
- published
- score
- truncated content
- provider
- optional answer text
- optional citations / grounding supports
- optional images / highlights
- fallback_attempted
- ignored_args
- seen_count, first_seen, last_seen
- last_query_hash

### Cache

- in-memory exact-match cache only
- TTL from `cache.ttl.web_search` (default: 1h)
- background DB sync every `cache.sync_interval` (default: 5m)
- no semantic cache in v0.1

## Tool 2: `fetch_content`

### Purpose

Fetch content for one or more URLs, or traverse content with `crawl`/`map` mode.

### Exposed tool args

```ts
{
  urls: string[]             // required, 1..20
  mode?: "extract" | "crawl" | "map"
  format?: "markdown" | "text"
}
```

Everything else is config-only.

### Config-owned options

- `defaultProvider`
- `primaryFallbackOrder`
- `depth`
- `max_chars`
- `max_depth`
- `limit`
- `select_paths`
- `query`
- `chunks_per_source`

### Response

```ts
{
  results: Array<{
    url: string
    title?: string
    content?: string
  }>
}
```

For `mode: map`, `content` is omitted.

### Recording table

`fetch_content_results`

Dedup key: `(url_hash, provider, mode)`

Stored fields include:
- normalized url
- title
- truncated content
- content_hash
- provider
- mode
- query
- depth
- format
- chunks_count
- pages_crawled
- fallback_attempted
- ignored_args
- seen_count, first_seen, last_seen
- last_query_hash

### Cache

- in-memory exact-match cache
- TTL from `cache.ttl.fetch_content` (default: 24h)
- background DB sync every `cache.sync_interval`

## Tool 3: `maps_search`

### Purpose

Run location-aware search via Gemini Maps grounding.

### Provider set

Gemini only in v0.1.

Brave `places` is intentionally excluded because it yields a different POI-style response shape; it can become a separate `places_search` tool or a v0.2 enhancement.

### Exposed tool args

```ts
{
  query: string              // required
  lat?: number
  lng?: number
  count?: number
}
```

### Response

```ts
{
  results: Array<{
    title: string
    uri: string
    placeId?: string
  }>
}
```

### Cache / DB

**None in v0.1.**

Every call hits Gemini directly. The user explicitly chose to avoid DB/cache storage for this tool.

## `/tools-config` command

### Purpose

Provide one shared user-facing entrypoint for changing configuration across all shipped tools.

### File

`opencode/command/tools-config.md`

### Supported commands

- `/tools-config`
- `/tools-config <tool>`
- `/tools-config <tool> show`
- `/tools-config <tool> reset`
- `/tools-config reset`

Where `<tool>` is one of:
- `web-search`
- `fetch-content`
- `maps-search`

### Interaction flow

1. Read current `~/.config/opencode/web-tools.yml`.
2. Ask which tool to configure.
3. Present **common options first**.
4. Offer **Advanced** branch for provider-specific options.
5. Write the YAML back only after confirmation.

### Usage / warning subcommands

- `/tools-config show-usage`
- `/tools-config suppress-warning <provider>`
- `/tools-config reset-usage <provider|all>`

## Cost and usage tracking

### Usage table

`provider_usage`

Per provider, per month (`YYYY-MM`):
- `calls`
- `units_used`
- `estimated_cost_usd`
- `tokens_input`
- `tokens_output`
- `warning_80_shown`
- `warning_90_shown`
- `budget_exceeded_shown`
- `suppressed`
- `last_call_at`

### Provider limits in v0.1

| Provider | Default limit | Warning | Hard stop |
|---|---|---|---|
| gemini | `$5.00` / month budget | 80% of budget | 100% of budget |
| brave | 2,000 requests / month | 80% | 90% |
| tavily | 1,000 credits / month | 80% | 90% |

### Gemini cost calculation

Gemini cost is **not** hardcoded in user config.

Instead, the plugin combines:
1. **LiteLLM price data** fetched and cached via a local copy of `model-pricing.ts`
2. **Gemini tool-fees supplement file** at `opencode/docs/models/gemini-tool-fees.yml`
3. **Request metadata** from Gemini API `usageMetadata`

Total per-call cost:

```text
token_cost(model, input_tokens, output_tokens)
+ tool_fee(model, tool_used)
= estimated_cost_usd
```

Tool fees:
- `google_search` grounding fee per call
- `googleMaps` grounding fee per call
- `url_context` = token-billed only (no separate fee)

### Model pricing helper

The plugin ships its own copy of:
- `pi-agent/src/runtime/model-pricing.ts`

New location:
- `opencode/plugins/web-tools/pricing.ts`

This keeps the plugin independent from `pi-agent` while reusing the proven LiteLLM fetch + cache approach.

### Approved Gemini defaults

Use `gemini-3.1-flash-lite` for:
- `searchModel`
- `urlContextModel`
- `mapsModel`

Rationale:
- cheapest Gemini 3.x token pricing
- still supports grounding
- aligned with fleet rule: Gemini 3.x only, no 2.5 routing

## Warning UX

When a provider crosses a threshold for the first time in the current month:

1. Append a warning preamble to the tool response string so the model sees it.
2. Emit a `tui.toast.show` event for user visibility.
3. Offer `/tools-config` follow-ups to:
   - change fallback order
   - suppress warnings until reset
   - reset usage counters manually

Suppression lasts until:
- the provider month rolls over, or
- the user manually resets usage.

- per-tool defaults

## Fleet integration

New component in `fleet-manifest.json`:

```json
{
  "id": "web-tools",
  "label": "Web Tools",
  "description": "Lean web-search/fetch/maps plugin with provider budgets and interactive config.",
  "atomic": true,
  "requires_bun": true,
  "default_on": true,
  "target_subdirs": ["plugins", "config", "command", "docs", "scripts"],
  "files": [
    "plugins/web-tools.ts",
    "config/web-tools.yml",
    "config/package.web-tools.json",
    "command/tools-config.md",
    "docs/models/gemini-tool-fees.yml",
    "scripts/install-web-tools.sh"
  ],
  "globs": ["plugins/web-tools/**"]
}
```

### Installer responsibilities

`scripts/install-web-tools.sh` must:
- copy `web-tools.yml`
- merge `package.web-tools.json` into the target config root package.json
- run `bun install` in the target config root if dependencies changed
- warn (not fail) when `BRAVE_API_KEY`, `TAVILY_API_KEY`, or `GEMINI_API_KEY` is unset
  (the plugin calls the provider REST APIs directly; no `bx`/`tvly` binary is required)
